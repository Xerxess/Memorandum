# 自定义布局

<https://developer.apple.com/documentation/uikit/uicollectionviewlayout>

- 决定集合视图边界内单元格、辅助视图和装饰视图的位置，并将该信息报告给集合视图
  - 补充视图 可以参考 header 与 footer
  - 装饰视图 通常认为是不可交互的
- 必须继承 UICollectionViewLayout
- 布局对象根据布局设计，定义集合视图中项目的位置、大小和视觉状态。
- 布局的视图由集合视图的数据源创建。

## UICollectionViewLayout 的核心作用

- 它不负责创建视图（那是 DataSource 的工作），它只负责计算几何属性
- 每当 CollectionView 需要展示内容时，它会向 Layout 询问一个UICollectionViewLayoutAttributes 对象。这个对象包含了视图的：
  - frame（坐标和尺寸）
  - center / size
  - transform（旋转、缩放）
  - alpha（透明度）
  - zIndex（层级）

## 核心重写方法及其调用时机

- prepare()
  - 时机：布局第一次生效前，或者因为数据源改变、手动调用 invalidateLayout() 导致布局失效后。
  - 原理：这是你的“预热站”。系统在询问具体的布局属性之前，先给你一个机会进行大规模的计算。
  - 建议：在这里计算并缓存所有的 LayoutAttributes。不要在查询方法里实时计算，否则滑动会掉帧。
- collectionViewContentSize
  - 时机：prepare() 调用之后。
  - 原理：CollectionView 需要知道内容的总体高度和宽度，以便设置内部 UIScrollView 的滚动范围（ContentSize）。
  - 注意：如果不返回正确的大小，CollectionView 可能无法滚动。
- layoutAttributesForElements(in rect: CGRect) -> [UICollectionViewLayoutAttributes]?
  - 时机：用户滑动屏幕时频繁调用。
  - 原理：系统给出一个矩形区域（通常是当前屏幕可见范围），问你：“这个框框里有哪些元素？它们分别在哪？”
  - 实现：遍历你在 prepare() 中缓存好的属性数组，返回那些与 rect 有交集的属性。
- layoutAttributesForItem(at indexPath: IndexPath) -> UICollectionViewLayoutAttributes?、
  - 时机：当系统需要某个特定位置的 Cell 信息时（例如执行插入、删除动画，或特定的逻辑跳转）。
  - 实现：直接从缓存中返回对应 IndexPath 的属性即可。
- shouldInvalidateLayout(forBoundsChange newBounds: CGRect) -> Bool
  - 时机：只要 CollectionView 的 Bounds 发生变化（比如滚动、屏幕旋转）就会询问。
  - 原理：如果你希望在滚动过程中动态改变布局（比如“瀑布流”里的悬浮表头，或者缩放动画），这里要返回 true。默认返回 false。

## 三种类型的视觉元素

- 单元格是布局中的主要元素
- 补充视图用于展示数据，但用户无法选择。使用补充视图来实现特定部分或整个集合视图的页眉和页脚等功能。补充视图是可选的，其使用和位置由布局对象定义。
- 装饰视图是视觉上的点缀，类似于徽章，它们无法被选中，并且与集合视图的数据本身没有关联。装饰视图是另一种类型的补充视图

## Methods to override 重写方法

提供集合视图在屏幕上放置内容所需的基本布局信息。如果您的布局不支持补充视图或装饰视图，请不要实现相应的方法。

- collectionViewContentSize 集合视图内容的宽度和高度。
- layoutAttributesForElements(in:) 检索指定矩形中所有单元格和视图的布局属性。
- layoutAttributesForItem(at:) 检索指定索引路径下对应单元格的项目的布局信息。
- layoutAttributesForSupplementaryView(ofKind:at:) （如果您的布局支持补充视图）
- layoutAttributesForDecorationView(ofKind:at:) （如果您的布局支持装饰视图）
- shouldInvalidateLayout(forBoundsChange:) 询问布局对象新的边界是否需要更新布局。

当集合视图中的数据发生变化，需要插入或删除项目时，集合视图会请求其布局对象更新布局信息。

- initialLayoutAttributesForAppearingItem(at:) cell出现动画 (起点)
- initialLayoutAttributesForAppearingSupplementaryElement(ofKind:at:) Supplementary出现动画 (起点)
- initialLayoutAttributesForAppearingDecorationElement(ofKind:at:) Decoration出现动画 (起点)
- finalLayoutAttributesForDisappearingItem(at:) cell消失动画 (终点)
- finalLayoutAttributesForDisappearingSupplementaryElement(ofKind:at:) Supplementary消失动画 (终点)
- finalLayoutAttributesForDisappearingDecorationElement(ofKind:at:) Decoration消失动画 (终点)

## 布局计算流程示例

1.初始化：在 prepare() 中初始化存储属性的数组。
2.遍历计算：通过 collectionView.numberOfItems(inSection:) 获取数据量。
3.坐标分配：维护一个记录每列当前高度的数组。每次遍历新 Item 时，将其放入当前高度最短的那一列，并根据列宽和 Item 高度计算出 frame。
4.缓存属性：为每个 Item 创建 UICollectionViewLayoutAttributes 对象，设置其 frame 后存入数组。
5.更新总高度：记录所有列中最长的一列高度，作为 collectionViewContentSize 的返回值。

## 利用失效上下文优化布局性能

- UICollectionViewLayoutInvalidationContext 精准打击。当布局需要改变时，它告诉 Collection View：“只重新计算这几个 Cell 的位置，其他的别碰。”
  - invalidateEverything: 布尔值。设为 true 就跟普通的 invalidateLayout() 一样全量刷新。
  - invalidatedItemIndexPaths: 告诉系统哪些具体的 Cell 需要重新计算。
  - invalidatedSupplementaryIndexPaths: 哪些 Header/Footer 坏了。
  - invalidatedDecorationIndexPaths: 哪些 背景/装饰视图 坏了。
contentOffsetAdjustment: 当布局改变导致滚动位置偏移时，用来微调滚动条位置。
- 调用 invalidateLayout() 时，Collection View 会重新计算所有 Item 的布局属性。
- 系统自动触发的场景
  - shouldInvalidateLayout(forBoundsChange:): 当用户滚动或旋转屏幕时，系统问你要不要刷新布局。你可以返回 true，并重写 invalidationContext(forBoundsChange:) 来微调哪些元素需要随滚动而动（比如实现 Sticky Header 吸顶效果）。
  - preferredLayoutAttributesFitting(_:): 当 Cell 使用 Self-Sizing（自动高度）计算完实际大小后，会触发 Invalidation Context 来更新布局。

```swift
// 在你的自定义 Layout 中
func updateLayoutForItem(at indexPath: IndexPath) {
    // 1. 创建一个布局失效上下文
    let context = UICollectionViewLayoutInvalidationContext()
    
    // 2. 标记特定的 IndexPath 失效
    context.invalidateItems(at: [indexPath])
    
    // 3. 触发局部更新
    self.invalidateLayout(with: context)
}

// 系统随后会只针对这个 indexPath 调用：
// layoutAttributesForItem(at:)
```

```swift
override func preferredLayoutAttributesFitting(_ layoutAttributes: UICollectionViewLayoutAttributes) -> UICollectionViewLayoutAttributes {
    // 1. 先获取父类默认提供的属性（通常是 Layout 根据 itemSize 算的）
    let attributes = super.preferredLayoutAttributesFitting(layoutAttributes)
    
    // 2. 根据内容计算“最自适应”的大小
    // UILayoutPriority.required 表示宽度固定（不希望宽度变）
    // UILayoutPriority.fittingSizeLevel 表示高度可以压缩
    let targetSize = CGSize(width: layoutAttributes.frame.width, height: 0)
    let size = self.contentView.systemLayoutSizeFitting(
        targetSize,
        withHorizontalFittingPriority: .required, 
        verticalFittingPriority: .fittingSizeLevel
    )
    
    // 3. 更新属性中的 frame
    var newFrame = layoutAttributes.frame
    newFrame.size.height = ceil(size.height) // 向上取整防止缝隙
    attributes.frame = newFrame
    
    return attributes
}
```

```swift
class MySectionBackgroundLayout: UICollectionViewLayout {
    
    private var decorationAttributes: [UICollectionViewLayoutAttributes] = []
    private var attributes: [IndexPath: UICollectionViewLayoutAttributes] = [:]
    private var headerCache: [Int: UICollectionViewLayoutAttributes] = [:]
    let cellSpacingV = 8.0 // cell 垂直方向间隔
    let cellSpacingH = 8.0 // cell 横向方向间隔
    let column = 4 // 列数
    let sectionSpacing = 8.0 // section间隔
    let sectionInnerMargin = 8.0 //section 内边距
    var contentSize:CGSize = .zero
    
    /// 获取实际可用于排版的有效宽度
    private var availableWidth: CGFloat {
        return collectionView?.bounds.inset(by: collectionView?.adjustedContentInset ?? .zero).width ?? 0
    }
    
    override init() {
        super.init()
        // 1. 注册装饰视图
        self.register(SectionBackgroundDecorationView.self, forDecorationViewOfKind: "SectionBackground")
    }
    
    required init?(coder: NSCoder) {
        fatalError("init(coder:) has not been implemented")
    }
    
    // 返回滚动区域
    override var collectionViewContentSize: CGSize {
        return CGSize(width: contentSize.width, height: contentSize.height)
    }
    
    
    // 布局准备，计算布局和收集 UICollectionViewLayoutAttributes
    override func prepare() {
        print("prepare")
        super.prepare()
        guard attributes.isEmpty, let collectionView = collectionView else { return }
        attributes.removeAll()
        decorationAttributes.removeAll()
        
        // 获取collectionView 显示宽度
        let collectionViewWidth = availableWidth
        // 计算每列的宽度
        let itemWidth = (collectionViewWidth - (Double(column) - 1.0)*cellSpacingH - sectionInnerMargin*2)/Double(column)
        let itemHeight = itemWidth
        var layoutSize:CGSize = .zero
        
        // 获取selections
        let sections = collectionView.numberOfSections
        for section in 0 ..< sections{
            let cells = collectionView.numberOfItems(inSection: section)
            var top = sectionInnerMargin
            var left = sectionInnerMargin
            for cellIndex in 0 ..< cells {
                let columnIndex = cellIndex%column
                if columnIndex == 0 && cellIndex != 0 {
                    top += itemHeight + cellSpacingV
                    left = sectionInnerMargin
                }
                let indexPath = IndexPath(item: cellIndex, section: section)
                let attrItem = UICollectionViewLayoutAttributes(forCellWith: indexPath)
                attrItem.frame = CGRect(x: left, y: top + layoutSize.height, width: itemWidth, height: itemHeight)
                attributes[indexPath] = attrItem
                left += itemWidth + cellSpacingH
            }
            
            // group 的attr
            let groupSize = CGSize(width: collectionViewWidth, height: top + itemHeight + sectionInnerMargin)
            let groupAttr = UICollectionViewLayoutAttributes(forDecorationViewOfKind:"SectionBackground",with: IndexPath(item: 0, section: section))
            groupAttr.zIndex = -1
            groupAttr.frame = CGRect(x: 0, y: layoutSize.height, width: groupSize.width, height: groupSize.height)
            decorationAttributes.append(groupAttr)
            layoutSize.height += groupSize.height + sectionSpacing
        }
        
        // 关键：即使 Header 的原始位置不在 rect 内，它也可能因为“吸顶”而出现在屏幕里
        // 所以我们需要手动检查并添加所有可见 Section 的 Header
        for section in 0..<collectionView.numberOfSections {
            let headerIndexPath = IndexPath(item: 0, section: section)
            let sectionFrame = decorationAttributes[headerIndexPath.section].frame
            let headerAttr = UICollectionViewLayoutAttributes(forSupplementaryViewOfKind: UICollectionView.elementKindSectionHeader, with: headerIndexPath)
            let headerHeight: CGFloat = 50
            headerAttr.frame = CGRect(x: sectionFrame.origin.x, y: sectionFrame.origin.y, width: sectionFrame.width, height: headerHeight)
            headerAttr.zIndex = 10 + section // 基础层级
            headerCache[section] = headerAttr
        }
        
        contentSize = CGSize(width: collectionViewWidth, height: layoutSize.height)
    }
    
    // 根据可见rect,返回可见区域的布局
    override func layoutAttributesForElements(in rect: CGRect) -> [UICollectionViewLayoutAttributes]? {
        print("layoutAttributesForElements")
        var allAttributes = attributes.values.filter { $0.frame.intersects(rect) }
        var decorationAttributes = decorationAttributes.filter { $0.frame.intersects(rect) } .map { attr in
            attr
        }
        
        allAttributes.append(contentsOf: decorationAttributes)

        
        // 关键：即使 Header 的原始位置不在 rect 内，它也可能因为“吸顶”而出现在屏幕里
        // 所以我们需要手动检查并添加所有可见 Section 的 Header
        // 实时获取吸顶后的 Header 属性
        for section in 0..<(collectionView?.numberOfSections ?? 0) {
            if let headerAttr = layoutAttributesForSupplementaryView(ofKind: UICollectionView.elementKindSectionHeader, at: IndexPath(item: 0, section: section)) {
                // 如果吸顶后的 Header 在可视区内，则添加
                if rect.intersects(headerAttr.frame) {
                    allAttributes.append(headerAttr)
                }
            }
        }
        
        return allAttributes
    }
    
    // 根据indexPath 返回布局
    override func layoutAttributesForItem(at indexPath: IndexPath) -> UICollectionViewLayoutAttributes? {
        // 根据索引直接从缓存拿
        return attributes[indexPath]
    }
    
    // 根据indexPath 返回补充视图的布局属性
    override func layoutAttributesForSupplementaryView(
        ofKind elementKind: String,
        at indexPath: IndexPath
    ) -> UICollectionViewLayoutAttributes?{
        print("layoutAttributesForSupplementaryView")
        let sectionFrame = decorationAttributes[indexPath.section].frame
        
        guard elementKind == UICollectionView.elementKindSectionHeader,
              let staticAttr = headerCache[indexPath.section] else { return nil }
        
        // 必须 Copy 一份，不要修改缓存原件
        let attributes = staticAttr.copy() as! UICollectionViewLayoutAttributes
        
        let contentOffsetY = collectionView!.contentOffset.y + collectionView!.adjustedContentInset.top
        
        // 计算吸顶坐标
        // 实现 Sticky Header 吸顶效果
        let headerHeight: CGFloat = 50
        let minY = sectionFrame.origin.y
        let maxY = sectionFrame.maxY - headerHeight
        let y = max(minY, min(contentOffsetY, maxY))
        
        attributes.frame = CGRect(x: 0, y: y, width: sectionFrame.width, height: headerHeight)
        attributes.zIndex = 1000 + indexPath.section // 越往后的 Section 层级越高
        
        return attributes
    }
    
    override func layoutAttributesForDecorationView(
        ofKind elementKind: String,
        at indexPath: IndexPath
    ) -> UICollectionViewLayoutAttributes?{
        if "SectionBackground" == elementKind {
            return decorationAttributes[indexPath.section]
        }
        
        return nil
    }
    
    override func shouldInvalidateLayout(forBoundsChange newBounds: CGRect) -> Bool {
        // 只要 bounds 发生变化（即滚动了），就刷新布局
        return true
    }
    
    override func invalidationContext(forBoundsChange newBounds: CGRect) -> UICollectionViewLayoutInvalidationContext {
        print("invalidationContext")
        let context = super.invalidationContext(forBoundsChange: newBounds)
        
        // 关键优化：手动标记所有的 Header 需要更新，而 Cell 不需要
        let allHeaderIndexPaths = headerCache.keys.map { IndexPath(item: 0, section: $0) }
        context.invalidateSupplementaryElements(ofKind: UICollectionView.elementKindSectionHeader, at: allHeaderIndexPaths)
        
        // 注意：不要调用 invalidateItems，那样会重新触发 prepare
        return context
    }
    
    // MARK: - 5. 初始动画属性
    override func initialLayoutAttributesForAppearingItem(at itemIndexPath: IndexPath) -> UICollectionViewLayoutAttributes? {
        print("initialLayoutAttributesForAppearingItem")
        // 先获取 prepare 中算好的最终状态
        let attributes = super.initialLayoutAttributesForAppearingItem(at: itemIndexPath) ?? attributes[itemIndexPath]?.copy() as? UICollectionViewLayoutAttributes
        
        // 设置“刚出生”时的样子：透明度为 0，向上偏移 20 像素
        attributes?.alpha = 0
        attributes?.transform = CGAffineTransform(translationX: 0, y: 100)
        
        return attributes
    }
}
```
