# 黑魔法

## NSObject.cancelPreviousPerformRequests(withTarget:selector:object:)

这段代码的主要作用是取消之前排队执行的特定延迟请求。它常用于“防抖”（Debouncing）或“节流”场景，确保在多次快速操作中只有最后一次能成功触发。

- 用于取消之前通过 perform(_:with:afterDelay:) 系列方法提交给当前运行循环（Run Loop）的异步延时任务。
- NSObject.cancelPreviousPerformRequests(withTarget:selector:object:) 会根据以下三个参数在**当前运行循环（Run Loop）**中查找并撤销匹配的任务：
  - withTarget: self：指定任务的接收者是当前对象。
  - selector: #selector(notifyAllObservers)：指定要取消的具体方法名。
  - object: nil：指定当时注册请求时传递的参数必须也是 nil。

```swift
import UIKit

class SearchViewController: UIViewController {

    @objc func handleSearchInputChange() {
        // 1. 先撤销之前还没来得及执行的“搜索请求”
        // 如果 0.5 秒内再次调用，之前的请求会被从 Run Loop 中踢出
        NSObject.cancelPreviousPerformRequests(
            withTarget: self, 
            selector: #selector(notifyAllObservers), 
            object: nil
        )

        // 2. 重新排队一个 0.5 秒后的任务
        // 只有用户停下来 0.5 秒，这个任务才会被真正执行
        self.perform(#selector(notifyAllObservers), with: nil, afterDelay: 0.5)
    }

    @objc func notifyAllObservers() {
        print("🔍 正在请求 API 进行搜索...")
        // 这里执行真正的刷新逻辑
    }
}
```

### 替代方案

- 现代替代方案：
  - DispatchWorkItem (最直接的替代)
  - Swift Concurrency (Task)
  - Combine (响应式方案)

#### DispatchWorkItem (GCD最直接的替代)

```swift
private var pendingRequestWorkItem: DispatchWorkItem?

func search(text: String) {
    // 1. 取消之前的任务
    pendingRequestWorkItem?.cancel()
    
    // 2. 创建新任务
    let requestItem = DispatchWorkItem { [weak self] in
        print("执行搜索: \(text)")
    }
    
    // 3. 存储并延迟执行
    pendingRequestWorkItem = requestItem
    DispatchQueue.main.asyncAfter(deadline: .now() + 0.5, execute: requestItem)
}
```

#### Swift Concurrency (Task)

```swift
private var searchTask: Task<Void, Never>?

func handleInput(_ text: String) {
    // 1. 取消旧任务
    searchTask?.cancel()
    
    // 2. 启动新任务
    searchTask = Task {
        try? await Task.sleep(nanoseconds: 500_000_000) // 0.5秒
        
        // 检查任务是否被取消（防止已取消的任务继续执行）
        guard !Task.isCancelled else { return }
        
        print("发送 API 请求: \(text)")
    }
}
```

#### Combine (响应式方案)

```swift
import Combine

private var cancellables = Set<AnyCancellable>()
let searchSubject = PassthroughSubject<String, Never>()

// 在初始化阶段配置
searchSubject
    .debounce(for: .seconds(0.5), scheduler: RunLoop.main) // 自动防抖
    .sink { text in
        print("搜索: \(text)")
    }
    .store(in: &cancellables)

// 调用时只需：
searchSubject.send("用户输入")
```

## objc_setAssociatedObject 与 objc_getAssociatedObject

objc_setAssociatedObject 是 Objective-C Runtime 库中的一个强大函数，它允许你在运行时将一个对象（关联对象）“关联”到另一个对象上。
谨慎使用：它被视为“黑魔法”，虽然方便，但滥用会增加调试难度，并可能导致难以追踪的内存泄露或性能问题。
Key 的唯一性：确保 Key 在全局是唯一的。推荐使用 static char kKey; 或 @selector。

```swift
public func objc_setAssociatedObject(_ object: Any, _ key: UnsafeRawPointer, _ value: Any?, _ policy: objc_AssociationPolicy)

public func objc_getAssociatedObject(_ object: Any, _ key: UnsafeRawPointer) -> Any?

public func objc_removeAssociatedObjects(_ object: Any)
```

```swift
import UIKit
import ObjectiveC // 必须导入

// 1. 定义一个唯一的 Key (地址是关键)
private var customIDKey: UInt8 = 0

extension UIButton {
    
    // 2. 定义一个计算属性，内部通过关联对象实现“存储”
    var customID: String? {
        get {
            // 获取关联对象
            return objc_getAssociatedObject(self, &customIDKey) as? String
        }
        set {
            // 设置关联对象
            objc_setAssociatedObject(
                self,               // 关联到谁？(当前按钮)
                &customIDKey,        // 存放在哪个格子？(Key 的地址)
                newValue,           // 存什么？(传入的字符串)
                .OBJC_ASSOCIATION_COPY_NONATOMIC // 怎么存？(String 推荐用 copy)
            )
        }
    }
}
```
