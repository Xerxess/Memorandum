# 开发小技巧

## 全局单例（Autoload）

全局单例（Autoload） 是指在游戏启动时自动加载、在整个游戏生命周期内一直存在，且可以从任何脚本访问的节点。

- 应用场景
  - 存储全局数据（如生命值、得分） 你在场景 A（关卡 1）修改了数据，切换到场景 B（关卡 2）后，数据依然存在。
  - 跨场景通信（全局信号总线） 解耦脚本的最佳方式。比如你想在“怪物死亡”时通知“UI 更新”，但它们不在一个场景里。
  - 场景切换器

- 如何创建单例
  - 新建一个脚本（例如 GameManager.gd）。
  - 点击菜单 项目 (Project) -> 项目设置 (Project Settings)。
  - 切换到 全局加载 (Autoload) 选项卡。
  - 点击文件夹图标选择你的 GameManager.gd。
  - 点击 添加 (Add)。确保 启用 (Enable) 已勾选。
  - 节点名称（默认通常是文件名）就是你在代码中访问它的“全局变量名”。

## Viewport Width Viewport Height 是什么作用

Viewport Width 和 Viewport Height 的作用可以理解为定义了你游戏的“逻辑画布尺寸”或“设计基准分辨率”。

- 获取“逻辑视口”大小 (最推荐) get_viewport().get_visible_rect().size
- var window_size = DisplayServer.window_get_size()

## 善用分组(Groups)

在 Godot 中，分组 (Groups) 就像是给节点贴上“标签”。它的核心作用是让你能跨越复杂的场景树层级，快速批量地找到并操作特定的节点。
编辑器操作：选中节点 -> 在右侧属性面板切换到 "Node" (节点) 标签 -> 点击 "Groups" (分组) -> 输入名称并点击 Add。

- 核心用途
  - 批量控制（最常用）
  - 身份识别（碰撞检测）
  - 快速获取列表

```gdscript
# 批量控制（最常用）
get_tree().set_group("lights", "color", Color.RED)

# 身份识别（碰撞检测）
func _on_area_2d_body_entered(body):
    if body.is_in_group("player"):
        take_damage()
    elif body.is_in_group("gold_coin"):
        collect_coin()

# 快速获取列表

var all_enemies = get_tree().get_nodes_in_group("enemies")
print("剩余敌人数量: ", all_enemies.size())
```

## 信号 (Signals)

信号（Signals）就是 Godot 的“快递/通知系统”。
解耦（Decoupling）的核心工具——让一个节点在发生某件事时（比如被点击、死亡、撞墙），不需要知道谁在监听，只管发出通知。

- 创建方式
  - 系统内置信号（最常用）
    - 操作：选中节点 -> 点击右侧 Node（节点） 面板 -> Signals（信号） -> 双击 pressed() -> 连接到脚本。
  - 自定义信号（代码实现）
  - 动态连接信号（进阶）

```gdscript
# Player.gd
signal health_changed(old_value, new_value) # 定义带参数的信号

func take_damage(amount):
    var old_hp = health
    health -= amount
    health_changed.emit(old_hp, health) # 发送信号
```

```gdscript
# 在生成怪物时
var monster = monster_scene.instantiate()
# 将怪物的“死亡”信号连接到 UI 的“更新分数”函数
monster.died.connect(_on_monster_died)
add_child(monster)
```

## 暂停功能

只需一行代码即可暂停或恢复整个游戏世界：
暂停游戏： get_tree().paused = true
恢复游戏： get_tree().paused = false

当你调用 get_tree().paused = true 时，默认情况下所有节点都会停止运行（包括输入处理和脚本执行）。为了让“暂停菜单”或“恢复按钮”在暂停状态下依然可用，你需要修改这些 UI 节点的 Process Mode：

在 检查器 (Inspector) 面板中找到 Process -> Mode（Godot 4.x）或 Pause -> Mode（Godot 3.x）属性：

- Inherit (继承): 默认值。跟随父节点的暂停状态。
- Always (始终): 无论游戏是否暂停，该节点始终运行（适合暂停菜单）。
- When Paused (暂停时): 仅在游戏暂停时运行。
- Pausable / Disabled: 分别对应仅在运行状态下工作或完全不运行。

## 监听游戏失去焦点

监听游戏窗口失焦（比如玩家切换到浏览器或点击桌面）在 Godot 中非常实用，通常用于自动暂停或静音。

> 方式一

```gdscript
# 挂载在你的主逻辑脚本或全局单例（Autoload）中：
func _notification(what):
    match what:
        NOTIFICATION_WM_WINDOW_FOCUS_OUT:
            # 窗口失去焦点（玩家切屏了）
            print("游戏已切出")
            get_tree().paused = true
            # 这里可以放置显示暂停菜单的逻辑
            
        NOTIFICATION_WM_WINDOW_FOCUS_IN:
            # 窗口重新获得焦点
            print("游戏已恢复焦点")
            # 注意：通常不要在这里自动取消暂停，最好让玩家手动点击“继续”
```

```gdscript
# 在 iOS 上，最可靠的通知常量是 NOTIFICATION_APPLICATION_PAUSED（进入后台）和 NOTIFICATION_APPLICATION_RESUMED（返回前台）。
func _notification(what):
    match what:
        # 当有电话打进来，或者玩家向上滑动进入多任务管理界面时触发
        NOTIFICATION_APPLICATION_PAUSED:
            print("iOS 应用进入后台/暂停")
            get_tree().paused = true
            # 建议在此处保存游戏存档，防止被系统强制杀进程
            
        # 当玩家重新点击图标回到游戏时触发
        NOTIFICATION_APPLICATION_RESUMED:
            print("iOS 应用恢复运行")
            # 通常保持暂停状态，显示一个“继续游戏”按钮让玩家手动点击
```

> 方式二

使用 DisplayServer 处理焦点和窗口状态的常见用法

```gdscript
func _ready():
    # 绑定回调函数处理窗口事件
    DisplayServer.window_set_window_event_callback(_on_window_event)

func _on_window_event(event):
    match event:
        DisplayServer.WINDOW_EVENT_FOCUS_IN:
            print("窗口获得焦点")
        DisplayServer.WINDOW_EVENT_FOCUS_OUT:
            print("窗口失去焦点")
        DisplayServer.WINDOW_EVENT_CLOSE_REQUEST:
            print("玩家点击了关闭按钮")
```
